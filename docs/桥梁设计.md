# 星期八桥梁设计（2026-11-25 定）

## 一句话定位
星期八是一座**桥**：24 小时在家里听着，听懂主人要什么，转给最擅长的 AI 或设备去做，再用语音把结果说回来。
**只开发桥，不造桥两头的东西**——付款、点外卖、修图、写文档等功能一律交给现成的 AI / App / 服务。

## 三层分工
| 层 | 谁 | 干什么 | 花费 |
|---|---|---|---|
| 调度员 | 本地 Gemma 4 12B | 日常的话：拆任务、派给谁、追问、汇报 | 免费，24 小时 |
| 主大脑 | Claude / GPT（两份会员） | 复杂的事：规划多步骤（如几天的旅行）、决定派给谁；写代码、查资料 | 贵，只在需要时用 |
| 专职成员 | 家电（Home Assistant）、美团“小美”/千问（外卖、打车、买东西）、携程类（旅行）…… | 干具体的活 | 用各家自己的能力 |

原则：**能用固定工作流就不让大模型思考**；反复出现的活“下放”给本地或专职成员。

## 一句话进来以后
1. 耳朵：唤醒 → 流式转写（边说边出字）→ 判断说完（文字 + 停顿）→ SenseVoice 定稿。
2. 调度：Gemma 按固定 JSON 输出任务清单：`{"tasks":[{"to","do","when","ask"}],"reply","confident"}`。
3. 升级规则（满足任一条就把原话转给 Claude/GPT 当主大脑，不靠 confident，实测它永远是 true）：
   - 任务派给了“Claude”成员；
   - 任务超过 4 件，或有前后依赖的多步骤计划（旅行、搬家这类）；
   - JSON 坏了 / 派给了不存在的成员；
   - 主人说“问问 Claude / GPT”。
4. 分派：在 AI 群聊里 @ 对应成员。**不碰文件的任务可以同时做**（开灯和点外卖互不影响）；“执行权同一时间只一个”只用于改代码。
5. 追问：成员的问题（如“想吃什么”）念给主人，主人的回答转回给该成员。
6. 汇报：全部做完或有需要主人决定的事时，一句话语音汇总，比如“灯开了，外卖小美在问你吃什么，电视等你洗完澡再开”。
7. 带条件的任务先挂起，条件到了再派（`bridge_pending.py`，存在 `groupchat\pending.json`，重启不丢）：
   - 定时的（“四十分钟后”“明天早上七点”“下午三点半”）：固定规则解析成具体时间，后台每 15 秒检查，到点派出；
   - 等条件的（“洗完澡后”“我回来以后”）：主人之后说“洗完了”“到家了”这类话（要有“完了/好了/回来了”，且和条件说的是同一件事）就派出；
   - “提醒”由星期八自己做：到点用语音说“提醒你：吃药”，托盘也弹一条；正在和人说话时最多等 2 分钟再说，免得插嘴；
   - 到点时成员还没接入（家电、美团……）：照样念出来，请主人自己处理，群里留一条；
   - 群里发“待办”看列表，“取消待办 2”取消一条（不叫 AI，不花额度）。

## 群成员要写清的东西（“名片”）
- 名字、会做什么（给 Gemma 分派用）、怎么接（Home Assistant / 屏幕操作 / 接口 / 命令行）、要不要主人确认（付款、删除这类由成员自己的流程负责确认，星期八只转话）。

## 实测记录
- 11-25：Gemma 4 12B 拆 12 句长口语，12/12 派对，每句 5～10 秒（首句含加载 13 秒）；qwen3.5:9b 每句 30～60 秒，不用。
  → 5～10 秒太慢，不能让主人干等：先马上回一句“好的，我来安排”，后台再拆。

## 接入顺序
1. 家电：Home Assistant（等主人告诉设备品牌）
2. 外卖：美团“小美”（不接华为）。**这台 Windows 电脑就是全屋主机，所有东西都装在它上面，不装手机。** 小美只有手机版的话，**不用模拟器**（主人不放心，App 也可能把模拟器当风险），改为给主机接一台真安卓手机（闲置旧手机常年插着充电），电脑通过 ADB 读屏幕文字、打字、点按，星期八把主人的话打进小美的输入框、把小美的回答读出来；用户在国外，测试时给国内家里点一单。
3. 旅行等其他专职 AI：按需加。
4. 以后哪家开放了 MCP / 接口，就换成接口，不再点屏幕。

## 不做的
- 自己开发付款、外卖、修图等功能。
- 自己从头写识别、回声算法（用 sherpa-onnx、WebRTC 等现成零件）。
- 把自己的会员额度中转给别人用。
